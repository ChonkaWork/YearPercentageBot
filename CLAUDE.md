# Repository guide for Claude

This repo holds two unrelated things:

1. **YearPercentageBot** (root: `build.gradle`, `src/`): a Spring Boot 3 / Java 21 Telegram bot
   that posts year progress. Build with `./gradlew build`.
2. **A portfolio of small Chrome extensions**, one self-contained folder each (`pastebot/`,
   `universal-copy/`, `clean-copy/`, `table-copy/`, `text-expander/`, `chat-exporter/`,
   `ai-chat-search/`, `page-watch/`, `video-speed/`, `progress-tab/`, `crypto-signal/`,
   `polymarket-analyzer/`).

Read before touching an extension:

- [`docs/CONCEPTS.md`](docs/CONCEPTS.md): what each extension is for, the "10 shots" strategy,
  metrics and kill rules.
- [`docs/design-system.md`](docs/design-system.md): Bootstrap 5.3 + Sass theme per extension,
  icons, fonts, in-page (shadow DOM) UI rules, brand colors.
- The extension's own `README.md`: how to use, build, test, permissions, limitations.

## Extension conventions

- Manifest V3, TypeScript, no UI framework. Bundled with esbuild (`scripts/build.mjs`) or Vite
  (`crypto-signal/`, `polymarket-analyzer/`). `dist/` is the loadable, store-ready build.
- **Self-contained folders**: own `package.json`, lockfile and tests. No imports across folders;
  copy shared helpers instead (each extension may be split into its own repo later).
- Pure logic (no DOM / Chrome APIs) lives in `src/core` (or `analysis/`, `services/`) and is
  unit-tested with vitest. UI never builds HTML from untrusted strings (use `textContent`).
- Local-first: no backend, analytics or remote code. Network only to the exact hosts a feature
  needs, declared as narrowly as possible.
- Minimal permissions, each justified in the README. Prefer `activeTab` + `scripting` over host
  permissions and `optional_host_permissions` over mandatory ones.
- E2E: `npm run test:e2e` builds a test variant into `dist-e2e/` and drives it in real Chromium
  via `playwright-core`. Native context menus and browser shortcuts can't be automated, so handlers
  are exposed through a test hook guarded by `__E2E__` and compiled out of `dist/`.
- Chrome silently refuses suggested shortcuts that clash with browser ones (e.g. `Ctrl+Shift+P`);
  e2e asserts that the suggested key is really assigned.
- Screenshots for READMEs are generated by e2e into `<folder>/screenshots/` (committed);
  `e2e/output/` is scratch (ignored).

Typical loop inside an extension folder:

```bash
npm install
npm run typecheck && npm test && npm run build
npm run test:e2e          # needs Chromium; set CHROMIUM_PATH if not auto-detected
```

Load in Chrome: `chrome://extensions` → Developer mode → Load unpacked → `<folder>/dist`.

## Environment notes (Claude Code on the web)

- Chromium for e2e: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` (headless works with
  extensions).
- The sandbox network blocks most real sites (GitHub pages, Stack Overflow, YouTube, LinkedIn,
  chatgpt.com, claude.ai, exchange and Polymarket APIs). Extensions are tested on local fixture
  pages and fixture API payloads; anything that depends on a live site or API is marked
  "unverified" in its README until someone checks it for real.

## Git

- Work on the branch you're given; one commit per extension (or per meaningful change) with a
  descriptive message.
- Never commit `node_modules/`, `dist/`, `dist-e2e/` or `e2e/output/`.
