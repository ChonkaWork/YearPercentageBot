# Інбокс ідей

Сирі ідеї та факти, ще не задачі. Дозріло — стає ішусом з лейблом `ai-lab`.

## 2026-08-23 — переїзд на cloud-модель
- Середовище: ефемерна VM, без cron/systemd/docker-daemon. Планувальник —
  Routines (research preview, мінімум година, деталі можуть змінитись).
- Push = єдиний спосіб зберегти стан. State/reports живуть на claude/* гілці
  runner-а; робота задач — у гілках `claude/ai-lab-<id>`. Main недоторканний.
- Preflight підтверджено з цієї VM: Maven Central, npm, plugins.gradle.org —
  усі доступні (HTTP 200).
- **Факт: у YearPercentageBot немає build-системи** (ні gradlew, ні pom.xml) —
  Java-код є, зібрати нічим. Перша реальна задача-кандидат для черги:
  "додати Gradle wrapper + Spring Boot build, acceptance: ./gradlew build".
- Черга = GitHub Issues з лейблом `ai-lab` (кинути ішус з телефону — секунди).
  Лейбл `ai-lab` ще треба створити в репо.
- Прогрів залежностей (Gradle кеш) — у setup script cloud environment,
  інакше кожен ран качає залежності заново.
- Краще три routine-рани по годині, ніж один довгий: ліміт рану 60 хв,
  рестарт ідемпотентний через закомічений state.
- Конектори в routine прибрані всі (за замовчуванням тягнуться Gmail/Calendar/
  Drive/Atlassian — нічному агенту не потрібні).

## Пізніше / потребує рішення
- Жорсткий guard на редагування тестів: зараз заборона тільки в промпті;
  можна дифати тестові шляхи після ітерації і фейлити задачу при їх зміні.
- Логи ітерацій не переживають VM (комітяться тільки state+report з хвостом
  помилки). Якщо для дебагу мало — комітити стислі логи окремо.
- Розділити state на окрему гілку claude/ai-lab-state, коли ailab-код
  замержиться в main.
- Автозакриття VERIFIED-ішусів або лейбли ai-lab:verified/failed — після
  того, як флоу з коментарями себе покаже.
